**Findings**

- `Critical`: The Christian “AR” flow is not real AR yet. The engine factory always instantiates `MockChristianArEngine`, and the controller defaults to `mock`, so scan/detect/place are timer-driven simulated states rather than world-tracked placement. The viewport is a camera feed with an overlay, not a native AR stack. [christianArEngineFactory.ts](/home/eiat/projects/oremus-expo/features/christian-prayer/ar/christianArEngineFactory.ts#L1) [useChristianArController.ts](/home/eiat/projects/oremus-expo/features/christian-prayer/hooks/useChristianArController.ts#L21) [MockChristianArEngine.ts](/home/eiat/projects/oremus-expo/features/christian-prayer/ar/MockChristianArEngine.ts#L22) [christian-ar-viewport.tsx](/home/eiat/projects/oremus-expo/features/christian-prayer/components/scenes/christian-ar-viewport.tsx#L96) [package.json](/home/eiat/projects/oremus-expo/package.json#L26) [app.config.ts](/home/eiat/projects/oremus-expo/app.config.ts#L5)

- `Critical`: The Christian 3D asset pack is not integrated. The asset folder only contains a README and manifest, the README says the `.glb` files still need to be added, and the model registry maps every required slot to `null`. That means the intended prayer-corner models cannot render in production. [README.md](/home/eiat/projects/oremus-expo/assets/models/christian/README.md#L1) [model-modules.ts](/home/eiat/projects/oremus-expo/features/christian-prayer/constants/model-modules.ts#L8) [christian-ar-viewport.tsx](/home/eiat/projects/oremus-expo/features/christian-prayer/components/scenes/christian-ar-viewport.tsx#L61)

The place screen updates transform state, but the rendered scene does not consume that state for actual placement; the fallback scene is static, and the 3D stage uses fixed layout constants. Users can “rotate” and “scale” without a real anchored update.
